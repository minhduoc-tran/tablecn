A field is one thing users can filter by, usually a column. You pass the list to the provider (`fields`), and core functions receive it as part of the context (`{ fields }`).

```ts title="lib/order-fields.ts"
import type { FieldDefinition } from "@querycn/filter-core"

export const orderFields: FieldDefinition[] = [
  { name: "number", label: "Order #", type: "text", operators: ["eq", "startsWith"] },
  { name: "customer", label: "Customer", type: "text" },
  {
    name: "status",
    label: "Status",
    type: "select",
    options: [
      { label: "Paid", value: "paid" },
      { label: "Pending", value: "pending" },
      { label: "Refunded", value: "refunded" },
    ],
  },
  { name: "tags", label: "Tags", type: "multiSelect", loadOptions: searchTags },
  { name: "amount", label: "Amount", type: "number", defaultOperator: "gte" },
  { name: "createdAt", label: "Created", type: "date" },
  { name: "paidAt", label: "Paid at", type: "datetime" },
  { name: "shipped", label: "Shipped", type: "boolean" },
]
```

The array order is the order of the field picker.

<Callout title="Keep the identity stable">
  Define fields at module scope (or wrap them in `useMemo`). A new array on every render makes the provider rebuild its context, and a new `loadOptions` function starts a new cache.
</Callout>

### `name`

The name is the contract between the UI, the URL and your backend:

- The URL stores it: `?status__eq=paid`.
- Serializers use it as the key: `filter[status][eq]=paid`, `status=paid`.
- [`applyFilter`](/docs/filter/client-filtering) reads `row[name]` by default.

Renaming a field breaks links that use the old name: its rules are dropped when the URL is decoded. If the backend expects a different name, keep the public one and alias it in the serializer with [`mapRule`](/docs/filter/serializers#maprule).

### `type`

The type decides which operators are offered, what value input is shown, how values are validated and how rows are compared on the client.

| Type | Operators, in display order | Default | Value in the URL |
| --- | --- | --- | --- |
| `text` | `contains` `notContains` `eq` `ne` `startsWith` `endsWith` `isEmpty` `isNotEmpty` | `contains` | string |
| `number` | `eq` `ne` `gt` `gte` `lt` `lte` `between` `isEmpty` `isNotEmpty` | `eq` | number, or the text as typed |
| `date` | `eq` `gt` `gte` `lt` `lte` `between` `isEmpty` `isNotEmpty` | `eq` | `"YYYY-MM-DD"` |
| `datetime` | `gt` `gte` `lt` `lte` `between` `isEmpty` `isNotEmpty` | `between` | ISO string, `"YYYY-MM-DDTHH:mm…"` |
| `boolean` | `eq` | `eq` | `true` / `false` |
| `select` | `eq` `ne` `isEmpty` `isNotEmpty` | `eq` | option `value` |
| `multiSelect` | `in` `notIn` `isEmpty` `isNotEmpty` | `in` | list of option values |

Some details that matter when you write the backend side:

- **number** keeps text that isn't a number. Someone typing `12,5` in a locale with decimal commas gets `"12,5"` in the URL and in the query, not a dropped rule. Your backend decides how to read it, so don't assume the value is always a `number`.
- **date** values are calendar days, never `Date` objects, so they don't shift across time zones. `2026-02-30` is rejected.
- **datetime** has no `eq`: matching an exact instant is almost never what users mean. The built-in input sends local time without a zone (`2026-09-25T14:30`); values with a zone (`…Z`, `+07:00`) are accepted too.
- **select** values are not checked against `options`. With async options the full list isn't known, and a URL can contain anything, so treat values as user input on the server.

Need another type, like a rating or a money amount with a currency? See [custom field types](/docs/filter/customization#custom-field-types).

### `operators` and `defaultOperator`

`operators` restricts a field to a subset of its type's operators, in the order you list them:

```ts title="Restricted operators"
{ name: "sku", label: "SKU", type: "text", operators: ["eq", "startsWith"] }
```

Ids the type doesn't support are ignored, so `operators: ["eq", "between"]` on a `text` field offers only `eq`.

When the user picks a field, the default operator is the first of these that's offered: `defaultOperator`, the type's default, the first operator in the list. Operators the [serializer](/docs/filter/serializers#inspect-and-supports) can't send are not offered, and don't count as offered here either.

### `options`

Static options for `select` and `multiSelect`. Values are strings. The search box matches labels, ignoring case and accents (`da nang` finds `Đà Nẵng`).

```ts title="Static options"
{
  name: "status",
  label: "Status",
  type: "select",
  options: [
    { label: "Paid", value: "paid" },
    { label: "Pending", value: "pending" },
  ],
}
```

### `loadOptions`

For long or changing lists. The UI calls it with the search text and an `AbortSignal`:

```ts title="lib/customer-fields.ts"
async function searchCustomers(search: string, signal: AbortSignal) {
  const response = await fetch(`/api/customers?q=${encodeURIComponent(search)}`, { signal })
  const customers: { id: string; name: string }[] = await response.json()
  return customers.map((c) => ({ label: c.name, value: c.id }))
}

export const fields: FieldDefinition[] = [
  { name: "customerId", label: "Customer", type: "select", loadOptions: searchCustomers },
]
```

How it behaves:

- The first list (empty search) loads as soon as the dropdown opens. Typing is debounced by 300 ms.
- A new search aborts the previous request through `signal`.
- While the next list loads, the current one stays on screen. A failed load shows an error with a retry button.
- Results are cached per search for the page session, keyed by the function itself. Two tables with a `status` field backed by different functions never share a cache. Call `clearFieldOptionsCache(field)` when the data changes (after creating a customer, on logout), or `clearFieldOptionsCache()` to clear everything.

Define the function at module scope. A new function on every render means a new cache and a new request every time.

### `resolveLabels`

A shared link can contain `customerId` values the user hasn't loaded yet. Without help, chips and the select would show the raw ids. `resolveLabels` fetches their labels:

```ts title="Resolved labels"
{
  name: "customerId",
  label: "Customer",
  type: "select",
  loadOptions: searchCustomers,
  resolveLabels: async (ids, signal) => {
    const response = await fetch(`/api/customers?${new URLSearchParams({ ids: ids.join(",") })}`, { signal })
    const customers: { id: string; name: string }[] = await response.json()
    return customers.map((c) => ({ label: c.name, value: c.id }))
  },
}
```

It is only asked about values that have no label yet (not in `options`, not in any loaded list). Values it leaves out are shown as they are, and it isn't asked about them again.

### `meta`

Free-form data for your own code. The filter doesn't read it, but it travels with the field into [`getAppliedRules`](/docs/filter/serializers#custom-serializers) and `mapRule`, which makes it a good place for backend details:

```ts title="Field meta"
{ name: "customer", label: "Customer", type: "text", meta: { column: "customers.full_name" } }
```

## Fields from JSON

A field list without functions is plain data, so it can come from a config file or an API:

```json title="order-fields.json"
[
  { "name": "customer", "label": "Customer", "type": "text" },
  {
    "name": "status",
    "label": "Status",
    "type": "select",
    "options": [
      { "label": "Paid", "value": "paid" },
      { "label": "Pending", "value": "pending" }
    ]
  },
  { "name": "amount", "label": "Amount", "type": "number", "operators": ["gte", "lte", "between"] },
  { "name": "createdAt", "label": "Created", "type": "date", "defaultOperator": "between" }
]
```

```ts title="fields.ts"
import type { FieldDefinition } from "@querycn/filter-core"

import orderFields from "./order-fields.json"

export const fields = orderFields as FieldDefinition[]
```

This is also what you'd pass from a Next.js server component to a client component. Functions (`loadOptions`, `resolveLabels`) can't cross that boundary, so add them on the client side.
