**tablecn** is a set of building blocks for the data tables every admin panel ends up with: filtering, sorting, paging and the URL state that ties them together. It follows the [shadcn/ui](https://ui.shadcn.com) way of working:

- **Logic ships as npm packages** under the `@querycn` scope. They are headless, typed and tested, and you update them like any dependency.
- **UI ships through a shadcn registry.** The CLI copies the components into your project, so you can restyle or rewrite them. Every component comes in three versions: [Radix UI](https://www.radix-ui.com), [Base UI](https://base-ui.com) and [React Aria](https://react-spectrum.adobe.com/react-aria/).

<Callout title="Work in progress">
  The packages are not published to npm yet. The docs describe the current state of the `main` branch.
</Callout>

## What's inside

The first finished piece is the **filter**: a conditional filter builder ("Where *Status* is *Paid* and *Amount* is between *10* and *50*") that keeps its state in the URL and turns it into whatever your backend understands.

The filter is a **standalone core**. It doesn't depend on the table, so you can use it on its own: above a list of cards, in a report, or only on the server to parse `?filters=` in an API route.

The table itself (built on [TanStack Table](https://tanstack.com/table)) is next. It will read the same applied filter, so the filter you set up today plugs into it without changes.

## Packages

| Package | What it is | Runs on |
| --- | --- | --- |
| `@querycn/filter-core` | Rules model, validation, URL codec, backend serializers, client-side filtering. Zero dependencies. | Anywhere: browser, Node, edge, any framework |
| `@querycn/filter-react` | Headless provider and hooks, URL adapters (browser history, react-router). | React 18+ |
| `@querycn/filter-next` | Next.js App Router adapter and `parseFilters` for server components. | Next.js 14.1+ |
| `filter-builder` (registry) | The filter UI: builder popover, rule rows, value inputs, chips. | shadcn/ui projects |

Each layer only depends on the ones above it, so you pick how much you take:

```txt
@querycn/filter-core        ← backend only: parse the URL, build the query
  └─ @querycn/filter-react  ← React with your own UI
       ├─ @querycn/filter-next   ← Next.js App Router
       └─ filter-builder (registry) ← ready-made shadcn UI
```

## Project structure

This site lives in the same monorepo as the packages:

```txt
tablecn/
├── apps/web/                      # this site (Next.js + Fumadocs)
│   ├── content/docs/              # MDX docs pages
│   ├── registry/{radix,base,aria} # filter UI, one folder per primitive library
│   ├── registry.json              # shadcn registry definition
│   └── public/r/                  # built registry (generated, not committed)
└── packages/
    ├── filter-core/               # @querycn/filter-core
    ├── filter-react/              # @querycn/filter-react
    ├── filter-next/               # @querycn/filter-next
    └── ui/                        # shared shadcn/ui components for this site
```

See [Development](/docs/development) to run it locally.
