**Try it:** the first column is on the right. Scroll the table sideways, drag a column's left edge to widen it, drag a header to move it, or open a column's **⋯** menu and its **Color** submenu.

## Set it up

Three things tell the table and its menus which way the page reads:

<Steps>
<Step>

### The page

Set `dir` on `<html>` (or on the element around the table), as for any right-to-left page:

```tsx title="app/layout.tsx"
<html lang="ar" dir="rtl">
```

The table's layout follows it: the first column, pinned columns and their shadows, the toolbar and the pagination.

</Step>
<Step>

### The table

Pass `dir` to `useDataTable`, so resizing follows the pointer:

```tsx title="components/orders-table.tsx"
const table = useDataTable({
  data,
  columns,
  getRowId: (order) => order.id,
  dir: "rtl", // [!code highlight]
})
```

</Step>
<Step>

### Your primitive library

Menus, selects and popovers read the direction from their library, not from the page. Wrap your app with its provider:

<Tabs items={["Radix UI", "Base UI", "React Aria"]}>
<Tab value="Radix UI">

```tsx title="app/providers.tsx"
import { Direction } from "radix-ui"

<Direction.Provider dir="rtl">{children}</Direction.Provider>
```

</Tab>
<Tab value="Base UI">

```tsx title="app/providers.tsx"
import { DirectionProvider } from "@base-ui/react/direction-provider"

<DirectionProvider direction="rtl">{children}</DirectionProvider>
```

</Tab>
<Tab value="React Aria">

React Aria takes the direction from the locale:

```tsx title="app/providers.tsx"
import { I18nProvider } from "react-aria-components"

<I18nProvider locale="ar-EG">{children}</I18nProvider>
```

</Tab>
</Tabs>

Without it, a column's **Color** submenu opens on the wrong side, and the arrow keys move the wrong way in menus.

</Step>
</Steps>

If your app switches direction with the language, derive all three from the same value.

## What follows the direction

| Part | Left-to-right | Right-to-left |
| --- | --- | --- |
| Columns | first column on the left | first column on the right |
| Pinned columns | "start" is the left edge | "start" is the right edge, and the shadow flips |
| Resizing | drag the right edge; <kbd>→</kbd> widens | drag the left edge; <kbd>←</kbd> widens |
| Moving a column | <kbd>←</kbd> / <kbd>→</kbd> move it the way the arrow points | the same: the arrow is the direction it moves on screen |
| Pagination | ‹ previous, › next | the arrows flip |
| Menus and submenus | open to the right | open to the left (with the provider above) |
| Header and cell text | aligned left | aligned right |

Everything is laid out with logical properties (`start` / `end`), so your own `meta` and classes should use them too: `ps-2` rather than `pl-2`, `text-start` rather than `text-left`.

## Translate

Right-to-left pages usually need their own texts too. The table ships English and Vietnamese; for another language, pass your messages to every component. See [Translate the UI](/docs/table/customization#translate-the-ui).

## Good to know

- **Numbers and dates** keep their own order inside a cell: `$5.00` and `2026-09-28` read left to right, as the browser renders them in any page.
- **Your shadcn components** (the dropdown menu's submenu arrow, the calendar's month arrows) are yours, from shadcn/ui: they flip as far as your copies do. Add `rtl:rotate-180` to an arrow icon that points the wrong way.
