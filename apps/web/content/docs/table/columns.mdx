Columns are plain [TanStack Table](https://tanstack.com/table/latest/docs/guide/column-defs) column definitions. `createDataTableColumnHelper` gives you a helper typed for the features `useDataTable` turns on, so `meta` and the sorting, pinning and sizing options are checked.

```tsx title="lib/order-columns.tsx"
import { createDataTableColumnHelper } from "@querycn/table-react"

import { createSelectionColumn } from "@/components/data-table/data-table-selection-column"

interface Order {
  id: string
  customer: { name: string }
  status: "paid" | "pending"
  amount: number
  createdAt: string
}

const column = createDataTableColumnHelper<Order>()

export const orderColumns = [
  createSelectionColumn<Order>(),
  column.accessor("customer.name", {
    header: "Customer",
    size: 200,
    meta: { required: true, defaultPinned: "start" },
  }),
  column.accessor("status", { header: "Status" }),
  column.accessor("amount", {
    header: "Amount",
    sortDescFirst: true,
    cell: ({ getValue }) => getValue().toFixed(2),
  }),
  column.accessor("createdAt", { header: "Created", meta: { defaultHidden: true } }),
  column.display({
    id: "actions",
    header: () => <span className="sr-only">Actions</span>,
    meta: { label: "Actions" },
    enableHiding: false,
    cell: ({ row }) => <OrderActions order={row.original} />,
  }),
]
```

Keep the array stable: define it at module level, or in a `useMemo`. A new array on every render rebuilds the table's columns.

The type of a single column is `DataTableColumnDef<TData>`, if you'd rather write the objects by hand.

## Column ids

Every column needs an id. TanStack Table derives it the same way the table's layout and URL do:

- an explicit `id` wins;
- otherwise `accessorKey`, with dots replaced by `_`: `customer.name` becomes `customer_name`;
- otherwise a string `header`.

The id is what appears in the URL (`?sort=-customer_name`), in the saved layout and in `data-column-id` on every cell. Renaming a column's id breaks links and saved layouts that use the old one; see [Layout](/docs/table/layout) for the second.

## Sorting from the URL

Only sortable columns are read from `?sort=`. A link like `?sort=secret_field` is dropped, so it never reaches your backend. `useDataTable` and `useTableQuery` work this out from the columns with `tableUrlOptions(columns, url)`.

To allow a narrower or wider list, set `url.sortableColumns` yourself. The server needs that list too, when it decodes the URL with `parseTableParams`: see [Rendering on the server](/docs/table/server-data#rendering-on-the-server).

## The selection column

`createSelectionColumn` comes with the registry block. It adds a checkbox per row and a header checkbox that selects the page:

```tsx title="Selection"
import { viTableMessages } from "@querycn/table-react/locales/vi"

import { createSelectionColumn } from "@/components/data-table/data-table-selection-column"

const columns = [createSelectionColumn<Order>(viTableMessages), ...otherColumns]
```

- It's pinned to the start and can't be hidden, sorted, resized, moved or unpinned, and it doesn't appear in the column menu.
- The optional argument is the table messages, for the checkboxes' labels ("Select all", "Select row").
- Which rows can be selected is up to `useDataTable({ enableRowSelection })`: `true`, or a function of the row. Disabled rows show a disabled checkbox.

The selection lives in the table state: read it with `table.getSelectedRowModel().rows`, or use the toolbar's [selection bar](/docs/table/components). It holds within one page and clears when the page, sort or filter changes.

## Grouped headers

Group columns (`column.group({ header, columns })`) render a header row above their leaves. Sorting, resizing, pinning and hiding work on the leaf columns. Moving columns by drag is turned off while there is more than one header row, because a leaf moved out of its group would break the group.
