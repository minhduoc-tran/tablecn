## Project structure

The docs site lives in the same monorepo as the packages:

```txt title="Monorepo layout"
tablecn/
├── apps/web/                      # this site (Next.js + Fumadocs)
│   ├── content/docs/              # MDX docs pages
│   ├── registry/{radix,base,aria} # table and filter UI, one folder per primitive library
│   ├── registry.json              # shadcn registry definition
│   └── public/r/                  # built registry
└── packages/
    ├── filter-core/               # @querycn/filter-core
    ├── filter-react/              # @querycn/filter-react
    ├── filter-next/               # @querycn/filter-next
    ├── table-react/               # @querycn/table-react
    └── ui/                        # shared shadcn/ui components for this site
```

## Requirements

- Node.js 20.6 or later
- pnpm 10 (the repo pins it in `packageManager`)

## Install dependencies

```bash title="Terminal"
pnpm install
```

## Start the dev server

```bash title="Terminal"
pnpm dev
```

Open [http://localhost:3000](http://localhost:3000) for the app and [/docs](/docs) for the documentation. `pnpm dev` builds the shadcn registry into `apps/web/public/r` first.

## Checks

Run these from the repository root:

```bash title="Terminal"
pnpm typecheck
pnpm lint
pnpm test
```

## Registry

The table and filter UI live in `apps/web/registry/{radix,base,aria}/{table,filter}`, described once in `apps/web/registry.json`. Rebuild the registry after changing either:

```bash title="Terminal"
pnpm registry:build
```

This writes `apps/web/public/r/{radix,base,aria}/*.json`: one JSON file per block and primitive library, each holding the component sources and their dependencies. Next.js serves them at `/r/<base>/<name>.json`, and at `/r/{style}/<name>.json` for the `@tablecn` namespace, which is what `npx shadcn add` downloads.

The folder is committed, so the registry can also be read straight from GitHub. After changing a registry component, run `pnpm --filter web registry:build` and commit `public/r` with it; CI fails when it's out of date. `pnpm dev` and `pnpm build` rebuild it too.

## Build for production

```bash title="Terminal"
pnpm build
```
